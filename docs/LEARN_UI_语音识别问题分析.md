# Learn UI 语音识别无反馈 — 问题分析与规划

## 一、现象描述

- 麦克风权限已授予（浏览器地址栏显示麦克风图标）
- 状态栏显示「正在监听，直接说话即可」
- 用户说话后**页面没有任何反应**：无文字转录、无「听到了」、无语音回复
- 说明 `recognition.onresult` 可能从未触发，或触发后未正确落入处理逻辑

---

## 二、根因分析

### 2.1 Chrome 语音识别依赖网络

Chrome 的 Web Speech API（SpeechRecognition）会把音频发送到 **Google 云端**做识别。

可能影响：

- 网络访问异常
- 在中国大陆等地区无法访问 Google → 识别请求失败或长时间无响应
- 会触发 `onerror`（如 `network`）或直接静默失败

### 2.2 `onend` 中自动 restart 可能失败

```js
recognition.onend = () => {
  if (listeningStarted) try { recognition.start(); } catch (_) {}
};
```

- `onend` 在回调中触发，不属于「用户手势」
- 部分浏览器要求麦克风必须在「用户操作」触发后调用
- 在 `onend` 里调用 `recognition.start()` 可能被浏览器拒绝，且错误被静默吞掉
- 结果：首次点击正常，一次静默/超时后 onend 触发，restart 失败，界面仍显示「正在监听」，但实际已停止

### 2.3 `isFinal` 可能长期为 false

```js
if (t && last.isFinal) handleUserInput(t);
```

- `interimResults = true` 时，会先收到大量 `isFinal === false` 的临时结果
- 若浏览器/网络异常，最终结果可能迟迟不到，或结构有差异
- 只处理 `isFinal` 会错过部分有效识别结果

### 2.4 结果对象结构差异

不同浏览器 / 前缀实现可能有差异：

- `e.results` 结构不同
- `last.isFinal` 可能为 undefined 或命名不同
- 需要兼容多种访问方式

### 2.5 缺少可观测性

- 无日志、无界面反馈
- 无法确认：是否收到 `onresult`、是否报错、`onend` 何时触发、restart 是否成功

---

## 三、规划目标

1. **明确语音识别链路**：start → onstart → 说话 → onresult → 处理逻辑 → 反馈  
2. **保证 restart 在用户手势下执行**：停止后不再自动 restart，改为「点击麦克风继续」  
3. **放宽结果处理条件**：在合理前提下也处理非 final 结果，提高容错  
4. **增加调试与状态展示**：便于定位问题，并给用户即时反馈  
5. **考虑无网络 / 国内环境**：预留说明和后续方案

---

## 四、实现规划

### 4.1 状态机

| 状态       | 显示文案                   | 可操作      |
|------------|----------------------------|-------------|
| `idle`     | 点击麦克风开始监听         | 点击麦克风  |
| `listening`| 正在监听，直接说话即可     | 等待语音    |
| `stopped`  | 已停止，点击麦克风继续     | 点击麦克风  |
| `error`    | 具体错误说明               | 点击麦克风重试 |

### 4.2 移除 onend 中的自动 restart

- `onend` 时：将状态设为 `stopped`，显示「已停止，点击麦克风继续」
- 用户再次点击麦克风时再调用 `recognition.start()`，符合用户手势要求

### 4.3 放宽 onresult 处理逻辑

- 优先处理 `isFinal === true` 的结果
- 若有临时结果且 `last.length > 0`，可对最后一条做一次处理（作为兜底，避免长期无反馈）
- 同一段话避免重复处理（简单去重或时间窗口）

### 4.4 即时反馈

- 收到任一 `onresult`（含 interim）时，在输入框或单独区域显示「正在识别：xxx」
- 识别完成后清空，并显示最终转录文本和回复

### 4.5 错误处理与展示

- 在 `onerror` 中解析常见错误：
  - `not-allowed` → 麦克风被拒绝
  - `network` → 网络问题（可能受 Google 服务影响）
  - `no-speech` → 未检测到说话（不当作致命错误）
- 将错误文案显示在状态栏或独立提示区

### 4.6 调试信息（可选 / 开发模式）

- 在页面角落展示：最近事件、最后收到的 transcript、错误信息
- 通过 URL 参数控制是否显示（如 `?debug=1`）

### 4.7 国内环境说明

- 在界面或文档中说明：Chrome 语音识别依赖 Google，国内可能不可用
- 建议：使用 Edge，或后续接入本地/国内 ASR 服务

---

## 五、代码变更点

1. 引入状态变量：`status = 'idle' | 'listening' | 'stopped' | 'error'`
2. 修改 `onend`：仅更新状态为 `stopped`，不再自动 `start()`
3. 修改 `onresult`：处理 final 结果；视情况处理最后的 interim 结果
4. 在输入框上方或旁增加「正在识别」临时显示区域
5. 完善 `onerror`：分类错误并更新状态与文案
6. 麦克风按钮：在 `idle` / `stopped` / `error` 时点击触发 `start()`
7. 可选：URL 带 `?debug=1` 时输出调试信息到页面
