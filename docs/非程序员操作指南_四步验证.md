# 非程序员操作指南：1～4 步怎么做

本文档面向**非程序员**，用最直白的步骤说明如何验证和搭建系统。

---

## 第 1 步：验证 Orchestrator 合体闭环

**目的**：确认「抓取快照 → 记录轨迹 → 点击按钮 → 再次抓取 + 差异对比」这一整条链路能跑通。

### 1.1 前置准备

1. **打开 DirectShell**
   - 按 `Win + E` 打开资源管理器
   - 进入：`D:\DirectShell\target\release\`
   - 双击运行 `directshell.exe`（若已运行可跳过）
   - 若没有此文件夹：说明 DirectShell 未编译，需要先完成 Phase 1 的 DirectShell 获取

2. **打开 Cursor**
   - 用 Cursor 打开本项目（SuperOS 文件夹）
   - 确保 Cursor 窗口在前台，且能看见界面上的 **Review** 按钮（或类似按钮）

### 1.2 执行验证

1. 在 Cursor 里按 **Ctrl + `**（反引号）打开底部终端
2. 在终端里依次输入下面两行命令，每行后按回车：

```text
cd d:\SuperOS
npx tsx scripts/verify-orchestrator.ts
```

3. 等待几秒，观察输出

### 1.3 怎样算成功？

- **成功**：终端出现类似 `[验证] 完成！任务状态: completed`
- **失败**：出现红色的错误信息，例如：
  - `findWindowByName 未找到`：DirectShell 未运行或 Cursor 窗口不可见
  - `timeout`：超时，可能是 DirectShell 或 ds_profiles 路径不对

### 1.4 检查轨迹是否被记录

1. 按 `Win + E` 打开资源管理器
2. 进入：`d:\SuperOS\data\trajectories\`
3. 找到今天日期的文件，例如：`trajectories_2026-03-13.jsonl`
4. 用记事本打开，若能看见很多行 JSON 文本（每行以 `{` 开头），说明轨迹已写入

## 第 2 步：MCP 打通（让 Cursor 能直接调 DirectShell）

**目的**：让 Cursor 在聊天中能通过 MCP 调用 DirectShell 工具，而不是只能跑本地脚本。

### 2.1 检查 Python 是否可用

1. 按 **Win + R** 打开运行框，输入 `cmd`，回车
2. 在黑色窗口里输入：

```text
py --version
```

3. 若显示 `Python 3.x.x`，说明已安装；若提示「不是内部或外部命令」，说明需要先安装 Python

### 2.2 安装 Python（若未安装）

1. 打开：https://www.python.org/downloads/
2. 下载 **Windows installer (64-bit)**
3. 双击安装，**务必勾选**「Add Python to PATH」
4. 安装完成后，关闭并重新打开 cmd，再执行 `py --version` 确认

### 2.3 安装 MCP 所需依赖

在 cmd 里依次执行：

```text
py -m pip install fastmcp requests
```

若出现错误，可尝试：

```text
python -m pip install fastmcp requests
```

### 2.4 确认 MCP 脚本路径

1. 打开资源管理器，进入 `D:\DirectShell\`
2. 确认存在 `ds-mcp` 文件夹
3. 进入 `ds-mcp`，确认有 `server.py` 文件  
   - 若没有：可能是 DirectShell 版本不同，需在 DirectShell 项目里查找 MCP 相关文件

### 2.5 在 Cursor 里配置 MCP

1. 在 Cursor 中按 **Ctrl + ,** 打开设置
2. 搜索框输入 **MCP**
3. 找到 **Edit in mcp.json** 或 **MCP Servers** 并点击
4. 在打开的 JSON 文件中，确认有类似下面的配置（路径按你电脑实际调整）：

```json
{
  "mcpServers": {
    "directshell": {
      "command": "py",
      "args": [
        "D:\\DirectShell\\ds-mcp\\server.py",
        "--profiles",
        "D:\\DirectShell\\ds_profiles"
      ],
      "cwd": "D:\\DirectShell"
    }
  }
}
```

5. 保存文件
6. **完全退出 Cursor 后重新打开**

### 2.6 怎样算 MCP 打通？

- 在 Cursor 的 **Composer** 或 **Chat** 中，若能看到 **directshell** 相关的工具/能力，说明已接入
- 若 MCP 列表里没有 directshell，多半是：Python 路径、`server.py` 路径或 `ds_profiles` 路径有误

## 第 3 步：路由层改进（解决「只打开不写不保存」）

**目的**：当你对 Jarvis 说「打开记事本，写一首诗，保存」时，系统应完成三步（打开、写、保存），而不是只打开记事本。

**说明**：这一步涉及代码修改，通常需要程序员或 AI 协助完成。你可以通过「说指令 → 看结果」来判断是否需要改进。

### 3.1 如何自测

1. 在 Cursor 中运行 Jarvis：  
   在终端执行：

```text
cd d:\SuperOS
npx tsx src/jarvis.ts
```

2. 在 Jarvis 提示输入时，输入：

```text
打开记事本，写一首诗，保存
```

3. 观察实际行为

### 3.2 怎样算成功？

- **成功**：记事本被打开 → 自动输入一首诗 → 自动保存（或弹出另存为并完成保存）
- **需要改进**：只打开了记事本，没有写诗或保存

### 3.3 若需要改进

把上面现象和具体指令一起发给程序员或 AI，说明：  
「我说了『打开记事本，写一首诗，保存』，但只打开了记事本，没有写和保存」，他们会根据 JARVIS_GODVIEW 蓝图调整路由与规划逻辑。

## 第 4 步：短视频流水线（最终目标）

**目的**：实现「Win11 自动化短视频生产流水线」的整体设计。

### 4.1 当前阶段

这一块尚在**规划与设计**阶段，还未开始实现。

### 4.2 需要你先想清楚的事

在实现前，建议你先回答下面问题（可以简单写下来）：

1. **素材来源**
   - 短视频画面从哪来？（例如：本地视频、截图、AI 生成图）
   - 配音/字幕是真人录还是用 TTS / 文字转语音？

2. **剪辑流程**
   - 用哪款剪辑软件？（如剪映、Premiere、CapCut 等）
   - 主要步骤是什么？（例如：加片段、加字幕、加配音、导出）

3. **发布平台**
   - 要发到哪些平台？（如抖音、YouTube、B 站等）
   - 是否需要自动上传、自动填写标题和描述？

4. **触发方式**
   - 希望怎么启动这条流水线？（如语音命令、定时任务、一键按钮）

### 4.3 下一步

把你在 4.2 中的回答整理成一份简短需求说明（哪怕只有几行），发给负责开发的人或 AI，他们会据此设计流水线的技术方案和实现步骤。

## 常见问题速查

| 问题 | 可能原因 | 处理方式 |
|------|----------|----------|
| `npx tsx` 不识别 | 未安装依赖 | 在项目目录执行 `npm install` |
| DirectShell 找不到 | 路径或未编译 | 检查 `D:\DirectShell\target\release\directshell.exe` 是否存在 |
| Python 找不到 | 未安装或未加入 PATH | 重新安装 Python 并勾选 Add to PATH |
| MCP 不显示 directshell | 配置或路径错误 | 检查 mcp.json 中的路径，重启 Cursor |
| 轨迹文件没有 | 验证脚本未成功执行 | 先确认第 1 步能跑通 |
