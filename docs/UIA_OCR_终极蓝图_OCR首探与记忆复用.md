# UIA + OCR 终极蓝图：OCR 首探 → 记忆复用

> 核心思想：**首次靠 OCR 智能定位 → 记住关键信息 → 后续直接复用**  
> 融合：双引擎、动态 UIA 检测、区域 OCR、多维度记忆、自动失效  
> 更新于 2026-03

---

## 一、核心思路（精准且正确）

你与豆包提炼的思路，本质是**工业级自动化产品的「缓存 + 复用」**，与 UiPath、影刀、Power Automate 等产品的策略一致。

| 阶段     | 操作逻辑                                   | 优势                     | 适用场景               |
|----------|--------------------------------------------|--------------------------|------------------------|
| **首次** | OCR 识别文字 → 定位控件 → 换算相对坐标 → 执行 | 通用，适配所有软件       | 新软件、首次用的控件   |
| **后续** | 查记忆库 → 直接用相对坐标 / ID / 快捷键    | 极快、0 Token、0 OCR 算力 | 重复操作               |

**核心价值**：
- ✅ 首次「智能兜底」：解决通用性（微信、剪映、任意 Electron）
- ✅ 后续「极致高效」：跳过 OCR，速度提升 10 倍+
- ✅ 全程 0 Token：记忆库本地，无云端消耗
- ✅ 自愈：失效自动剔除，下次重新 OCR

## 三、统一记忆库设计（多维度）

### 3.1 记忆维度与优先级

| 维度           | 优先级 | 适用场景       | 举例                         |
|----------------|--------|----------------|------------------------------|
| 语义快捷键     | 1      | 系统级操作     | 保存→^s，搜索→^f             |
| AutomationId   | 2      | 标准 Win32     | 记事本输入框（微信常无效）   |
| 文件路径/窗口名| 3      | 打开软件       | 微信→D:\WeChat\WeChat.exe    |
| **相对坐标**   | 4      | 固定布局       | 输入框 = 窗口(0.75, 0.92)    |
| 绝对坐标       | 5      | 临时兜底       | 仅当以上都失效               |

**关键**：**一律记相对坐标**，不记绝对坐标  
- 绝对 (100,200)：窗口一移动即失效  
- 相对 (0.75, 0.92)：窗口挪动、缩放仍可用  
- 换算：`xRel = (centerX - winLeft) / winWidth`，yRel 同理  

### 3.2 记忆来源（谁可以写入）

| 来源           | 写入时机                     |
|----------------|------------------------------|
| 用户教学       | Learn UI 说「这是 XXX」      |
| OCR 发现       | 首次 OCR 定位成功           |
| UIA 发现       | UIA 找到元素，取 BoundingRect 换算 |
| 应用 Profile   | 硬编码（剪映导出等）        |

### 3.3 自动失效逻辑

| 触发条件           | 动作                           |
|--------------------|--------------------------------|
| 执行记忆坐标后失败 | 删除该条记忆，下次走 OCR       |
| 可选：连续 N 次失败| 永久移除，避免反复无效重试     |
| 可选：TTL           | 如 30 天未使用则弱化优先级     |
| 手动标记「永久」   | 如剪映导出按钮，布局极少变化   |

## 四、调用流程（先查记忆，再 OCR）

```
用户指令：「给微信张三发消息」
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│ 1. 查记忆库：「微信|输入框」「微信|张三」等              │
└─────────────────────────────────────────────────────────┘
    │
    ├─ 命中 ──▶ 取相对坐标/快捷键/ID
    │              │
    │              ▼
    │         执行（点击/按键）
    │              │
    │              ├─ 生效 ──▶ 完成 ✅
    │              │
    │              └─ 失效 ──▶ 删除该记忆
    │                           ▼
    │                       走 OCR 重新定位
    │
    └─ 未命中 ──▶ 走 OCR（或 UIA，若为标准软件）
                     │
                     ▼
                 OCR 定位成功
                     │
                     ├─ 换算相对坐标
                     ├─ 写入记忆库
                     └─ 执行点击 ✅
```

## 五、与双引擎的完整整合

### 5.1 大流程图

```
clickByName(target = "微信|输入框")
    │
    ├─ 1. 语义快捷键命中？ ──▶ sendKeys，返回
    │
    ├─ 2. 记忆库命中？
    │      ├─ 是 ──▶ 取相对坐标 → 点击
    │      │           ├─ 生效 → 返回 ✅
    │      │           └─ 失效 → 删记忆 → 继续
    │      └─ 否 → 继续
    │
    ├─ 3. 应用专用坐标？（剪映等） ──▶ 点击，返回
    │
    ├─ 4. 应用是否「OCR 优先」？
    │      ├─ 动态判断：最近 UIA 失败率 ≥ 阈值 → 直接 OCR
    │      └─ 否 → UIA 查找
    │
    ├─ 5. UIA 查找（标准软件）
    │      ├─ 成功 → 执行，可选写入记忆库
    │      └─ 失败 → 计入统计 → 继续
    │
    └─ 6. OCR 引擎（兜底 + 首探）
           ├─ 区域截图（非全屏）
           ├─ 本地 OCR
           ├─ 模糊匹配 + 优先级
           ├─ 取 bbox 中心 → 换算相对坐标
           ├─ 点击 ✅
           └─ 写入记忆库（供后续复用）
```

### 5.2 各层职责

| 层         | 职责                                     |
|------------|------------------------------------------|
| 记忆层     | 多维度记忆库，查/写/失效                 |
| 决策层     | 查记忆 → UIA/OCR 选择 → 执行顺序        |
| UIA 层     | 标准控件查找，动态失败率统计             |
| OCR 层     | 区域截图、识别、匹配、相对坐标换算、回写 |
| 执行层     | click、type、keys（沿用现有）            |

| 0.3  | 区域截图                     | screenshotRegion(hwnd, region)  |

### Phase 1：OCR 首探 + 记忆写入（3–5 天）

| 步骤 | 内容                                   | 产出                           |
|------|----------------------------------------|--------------------------------|
| 1.1  | 本地 OCR 模块                          | PowerShell/C# 调 Windows.Media.Ocr |
| 1.2  | 文字匹配（模糊 + 优先级）              | ocrFindText(region, keywords)   |
| 1.3  | OCR 成功 → 换算相对坐标 → 写入记忆库   | 集成到 clickByName              |
| 1.4  | 微信输入框试点                         | 首次 OCR，后续走记忆            |

### Phase 2：动态 UIA 检测 + 记忆失效（2–3 天）

| 步骤 | 内容                                   | 产出                           |
|------|----------------------------------------|--------------------------------|
| 2.1  | 按应用统计 UIA 失败率                  | appUiaFailureRate(appName)     |
| 2.2  | 失败率 ≥ 阈值 → OCR 优先               | 无需手写名单                   |
| 2.3  | 记忆执行后校验                         | 输入框：FocusedElement 是否 Edit |
| 2.4  | 校验失败 → 删除记忆，下次 OCR          | 自愈闭环                       |

### Phase 3：多维度扩展（2–3 天）

| 步骤 | 内容                                   | 产出                           |
|------|----------------------------------------|--------------------------------|
| 3.1  | 加入 AutomationId 记忆                 | UIA 成功时写入                 |
| 3.2  | 路径/窗口名记忆                       | 打开软件时复用                |
| 3.3  | 剪映、浏览器等复用                    | 通用记忆库，无需重写          |

### Phase 4（可选）：图标兜底

| 步骤 | 内容                                   | 产出                           |

## 七、最小可行版本（MVP）

**目标**：先跑通「OCR 首探 → 记相对坐标 → 后续复用」的单点链路。

| 序号 | 任务                                             |
|------|--------------------------------------------------|
| 1    | 实现 Windows.Media.Ocr 调用（PowerShell 或 C#）  |
| 2    | 实现「截微信窗口下半区 → OCR → 找「输入」/「发送」」 |
| 3    | 找到后换算相对坐标，写入 learned_actions         |
| 4    | clickByName 查 learned_actions 时能命中「微信\|输入框」 |
| 5    | 验证：首次 OCR，第二次直接点坐标                 |
| 6    | 验证：窗口挪动后，相对坐标仍有效                 |

**产出**：微信输入框可「首次 OCR、后续复用」，作为全链路样板。
