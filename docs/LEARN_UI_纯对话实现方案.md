# Learn UI 纯对话实现方案（含语音识别替代）

## 一、当前已有能力（纯对话）

系统已实现**不依赖 F12 / 快捷键**的对话流程：

1. **说「这是XXX」** → 系统语音提示「请把光标移到目标上，三秒后记录」→ 3、2、1 倒计时 → 用 **GetCursorPos + WindowFromPoint** 获取光标下窗口，保存坐标
2. **说「看看画面」** → 同上流程 → 截取光标下窗口 → Vision 描述
3. **说「执行某某」** → 从知识库读取坐标并点击

核心：**光标下窗口**（`getWindowUnderCursor`），不依赖前台焦点。用户在前端说话时，前台是浏览器，但「把光标移到目标」后，即可正确记录。

## 二、语音识别问题与替代方案

### 2.1 当前问题

- Chrome 的 Web Speech API 将音频发往 **Google 云端**，国内常无响应或静默失败
- Edge 有时可用（部分用户反馈）
- 无网络或网络异常时完全失效

### 2.2 替代方案（含网上调研）

| 方案 | 离线 | 中文 | 集成复杂度 | 适合 Learn UI |
|-----|------|------|------------|---------------|
| **Vosk-Browser** | ✅ | ✅ | 中 | ⭐⭐⭐ 推荐 |
| **Whisper.cpp WASM** | ✅ | ✅ | 中 | ⭐⭐ 适合长句 |
| **输入框打字** | ✅ | ✅ | 已有 | ⭐⭐⭐ 立即可用 |
| **本地后端 ASR** | ✅ | 视实现 | 高 | ⭐ 需额外服务 |

### 2.3 推荐路径

#### 路径 A：立即可用 — 强化输入框

- 已支持输入框发送
- 建议：在欢迎语和状态栏更突出「语音不可用时，请用输入框」
- 在输入框 placeholder 示例更清晰，如：「例如：这是剪映的开始创作按钮」

#### 路径 B：Vosk-Browser 离线识别（1–2 天）

- **npm**: `vosk-browser`
- **模型**：约 40–80MB 中文小模型，放 `public/models/`
- **流程**：用户点击麦克风 → 加载模型（首次慢）→ 实时识别，`result` / `partialresult` 回调
- **优点**：完全离线、国内可用、延迟 <500ms
- **参考**：
  - [Vue3集成Vosk-Browser](https://cloud.baidu.com/article/3967926)
  - [vosk-browser npm](https://www.npmjs.com/package/vosk-browser)

#### 路径 C：本地 Ollama + Whisper（若已有 Ollama）

- Ollama 支持 `whisper` 模型，可做服务端 ASR
- 前端：录音 → 发送 base64 到后端 → 调用 Ollama API 转写 → 返回文本
- 优点：与项目 Local-First 理念一致，数据不出本机
- 缺点：需运行 Ollama，延迟比 Vosk 高

## 三、对话式学习流程优化

### 3.1 已完成的优化

- 状态机：idle → listening → stopped，不再在 `onend` 自动 restart
- 放宽 `onresult`：优先 `isFinal`，避免长期无反馈
- `liveHint` 显示「正在识别：xxx」
- 错误展示（network、not-allowed 等）

### 3.2 可进一步增强

1. **interim 兜底**：若 3–5 秒内没有 `isFinal`，可对最后一条 interim 结果做一次处理（防静默）
2. **双模式切换**：界面提供「语音模式 / 打字模式」开关，语音失败时引导用打字
3. **Edge 提示**：在 Chrome 下语音失败时，提示「可尝试使用 Edge 浏览器」

## 四、纯对话流程总结

```
用户（语音或打字）：「这是剪映的开始创作按钮」
    ↓
系统：语音 + 文字「好的，请把光标移到目标上，三秒后记录」
    ↓
3、2、1 语音倒计时
    ↓
getWindowUnderCursor() → 保存到知识库
    ↓
系统：语音 + 文字「已记住 剪映|开始创作」
```

**关键**：不依赖前台窗口，不依赖 F12，仅依赖「用户把光标移到目标」这一动作，完全通过对话完成教学。
