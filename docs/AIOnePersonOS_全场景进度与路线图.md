## 第一部分：终极愿景与四大场景

### 一、你的终极愿景（归纳）

你希望做到：**给电脑一个自然语言指令，系统自主完成复杂、多步骤、跨应用的任务，无需人工干预**。归纳为四大核心场景：

---

### 场景一：短视频全流程生产

**用户说**：「我今天要做一个关于 XXX 的短视频」

**系统应做到**：
1. 拟定话题 / 用豆包/DeepSeek 等免费 AI 生成文案
2. 复制文案 → AI 做分镜描述
3. 用文生图软件（SD/通义万相等）挨个粘贴分镜 → 生成图片 → 下载
4. 用图生视频软件（Runway/可灵/即梦）生成视频
5. 导入剪映 → 加字幕/配音 → 导出 → 可选发布

**依赖能力**：LLM 文案、文生图 API/软件控制、图生视频、剪映流水线、TTS、字幕、发布

---

### 场景二：全网研究 + 复杂报告编写

**用户说**：「帮我做一个关于 XXX 的复杂研究报告」

**系统应做到**：
1. 全网搜索相关资料
2. 结合 AI 多轮对话整理、分析
3. 编写研究报告或材料
4. 保存到指定路径并回馈用户

**依赖能力**：ResourceHunter 增强、ResearchAgent 增强、LLM 多轮对话、文档保存、任务拆分

---

### 场景三：电影推荐 + 资源下载

**用户说**：「我想看电影，给我推荐几部」→ 用户选择 → 「直接帮我找到免费可下载资源，保存到我指定的安装路径」

**系统应做到**：
1. 理解偏好 → 推荐电影列表
2. 用户选择后 → 全网搜索免费下载资源（magnet/云盘）
3. 下载到用户指定路径（aria2 等）

**依赖能力**：推荐逻辑（LLM/规则）、ResourceHunter、downloadExecutor、指定路径下载

---

### 场景四：资料拆解与长期执行

**用户说**：「我需要 XXX 样子的资料」

**系统应做到**：
1. 拆解为子任务（搜什么、从哪下、存哪、格式等）
2. 长期执行（可跨天、可中断续跑）
3. 定期汇总/汇报

**依赖能力**：任务拆解、持久化任务队列、断点续传、进度汇报

## 第七部分：TuriX-CUA 分析与可选集成

> 基于 [TuriX-CUA GitHub](https://github.com/TurixAI/TuriX-CUA) 及 OpenClaw Skills 文档的分析结论

### 一、TuriX 核心能力简述

| 能力 | 说明 |
|------|------|
| **OpenClaw Skill** | 可被 OpenClaw 调用，作为桌面操作子 Agent；ClawHub 已发布 [turix-cua](https://clawhub.ai/Tongyu-Yan/turix-cua)；Windows 本地 skill 在 `multi-agent-windows` 分支，含 `run_turix.ps1` |
| **MCP-ready** | 可接入 Claude for Desktop 或任意支持 MCP 的 Agent |
| **Skills（Markdown playbooks）** | Planner 选技能、Brain 按指令执行，类似我们的规则兜底 |
| **Ollama 支持** | 可用本地 Qwen3-VL 等，符合 Local-First |
| **DuckDuckGo 集成** | 信息收集加速，与 ResearchAgent 方向一致 |
| **Recoverable Memory** | 可恢复记忆压缩，可借鉴 learnedActions 演化 |
| **Roadmap** | Q2 2026：Persistent Memory、Learning by Demonstration |

### 二、与 AIOnePersonOS 的差异

| 维度 | AIOnePersonOS | TuriX |
|------|---------------|-------|
| 技术栈 | TypeScript + UIA + DirectShell | Python + 视觉模型 + 截图 |
| 架构 | Jarvis + parseIntent + runA11ySequence | OpenClaw / MCP 调用，自成一体会话 |
| 探索 | 规则 + 预设路径，缺 GUI 探索 | 视觉模型自主规划 + 试错 |
| 集成方式 | 主控为 Jarvis | 作为子 Agent 被调用 |

### 三、是否有必要纳入计划？

**有参考价值，但不必作为当前执行项。**

| 纳入方式 | 价值 | 建议 |
|----------|------|------|
| **直接集成 TuriX 二进制** | 中 | 需 Python 环境 + 视觉模型，与现有 TS 栈分离；集成成本高，**暂不纳入** |
| **接入 OpenClaw + TuriX** | 低 | 你主控是 Jarvis，非 OpenClaw；切换架构成本大，**不纳入** |
| **MCP 调用 TuriX（探索兜底）** | 高 | 当 parseIntent 未命中且 exploreAndTry 失败时，通过 MCP 委托 TuriX 执行 GUI 探索；**纳入为后续可选 Phase** |
| **借鉴 Skills / Recoverable Memory** | 高 | Skills ≈ 我们的规则兜底 + 技能描述；可参考其 Markdown 结构优化 `buildRuleFallbackSteps` 等；**文档层面借鉴，不新增依赖** |

### 四、具体纳入方式（可选，不阻塞主计划）

将 **「Phase E：TuriX MCP 探索兜底（可选）」** 放入第四优先之后：

| 序号 | 动作 | 触发条件 | 预估 |
|------|------|----------|------|
| 12 | 调研 TuriX 是否提供 MCP Server，或能否通过 subprocess 传任务取结果 | 探索闭环 Phase B 做完且仍不足时 | 1～2 天 |

**执行顺序**：先完成 P0 收尾、P1 导入、文案、分镜、文生图、图生视频、研究、电影等；探索闭环自建（effectChecker → exploreAndTry）优先；TuriX 集成作为**长期可选增强**，不改变当前主路径。

## 第八部分：向量视觉记忆（远期规划，预留接入）

> 已写入计划，后续考虑实现；当前开发需考虑未来接入可能性。

### 一、概念与价值

| 对比项 | OCR | 向量视觉（Vector Eyes） |
|-------|-----|-------------------------|
| **本质** | 图片 → 文字（Tesseract 等） | 截图 → VLM → 向量 embedding → 下次相似度匹配 |
| **输出** | 一段文本 | 可存储的视觉表征 + 坐标，下次直接点击 |
| **适用** | 有文字控件、UIA 找不到时 | 图标、无文字控件、网页特殊元素、样式变化 |
| **与 TuriX** | TuriX 可能用 OCR 作辅助 | TuriX 核心是「截图 → VLM → 动作」，向量视觉是轻量替代/补充 |

**价值**：当 UIA 找不到、OCR 也读不出文字时，用「向量眼睛」把控件转成 embedding 存储；下次用相似度匹配定位，再结合 Rust/SuperEye 执行点击。

### 二、教导模式逻辑（远期）

1. 用户指屏 + 语音：「这是我要点击的按钮」
2. Rust/UIA 先摸 UIA 树；若找到，存 UIA 路径/坐标（最快、最稳）
3. 若 UIA 摸不到（如特殊网页），截图 → 调用视觉模型 → 得到目标区域的 embedding → 存入 vectorStore
4. 下次：向量相似度检索 → 取坐标 → 控制鼠标点击

### 三、纳入计划与顺序

| Phase | 内容 | 顺序 |
|-------|------|------|
| Phase A～C | 效果校验、简单探索、路径记忆 | 当前优先 |
| Phase D | 目标解析（可选） | 其后 |
| Phase E | TuriX MCP 探索兜底（可选） | 其后 |
| **Phase F** | **向量视觉记忆（远期）** | 最后，视资源与需求决定 |

### 四、未来接入设计考虑（当前开发需预留）

为便于后续接入，以下模块设计时预留扩展点：

| 模块 | 预留点 | 说明 |
|------|--------|------|
| `clickByName` | 在 UIA / OCR / 缓存均失败后，调用可插拔的 `visualFallback?(target, hwnd)` | 返回 `{ x, y } \| null`，实现时可接 vectorEyes |
| `learnedActions` | 扩展 `LearnedRecord` 支持 `embedding?: number[]` | 与现有坐标并存，后续 vectorStore 可复用 |
| 教导/录制流程 | 用户指屏时刻，可导出「截图 + 区域 ROI」 | 供后续生成 embedding 并写入 vectorStore |
| 配置 | `.env` 预留 `VECTOR_EYES_ENABLED=0`、`VISION_MODEL_URL=` | 启用时再实现具体逻辑 |

**原则**：不改变现有 UIA 优先、OCR 兜底的主链路；向量视觉作为第三层 fallback，按需接入。
